# Go chassis

- Check and test from the root of the repository: `go vet ./packages/chassis/... && go test ./packages/chassis/...`. The integration tests need a PostgreSQL in `TEST_DATABASE_URL` and a Kafka in `TEST_KAFKA_BROKERS` (README), and each is skipped without the one it needs; `internal/chassistest` gives each test its own database and topic.
- One package per concern (`server`, `health`, `metrics`, `config`, `logging`, `postgres`, `event`, `consumer`, `outbox`, `queryclient`, `token`); a service imports only the ones it needs, and each package has its own tests.
- It never imports a service and holds no rule of any bounded context.
- It is a thin chassis assembled from the libraries ADR-07 chose, one per concern, not a framework and not written from scratch: `server` on `net/http` (the handlers are the strict server `oapi-codegen` generates in each service), `health`, `config` and `logging` on the standard library (`os.Getenv`, `log/slog`), `metrics` on `prometheus/client_golang`, `postgres` on `jackc/pgx/v5` with `pressly/goose`, `event` on `go-jsonschema` for the envelope and on Watermill with `watermill-kafka` for the publisher, `consumer` on Watermill with `watermill-kafka`, `outbox` on `watermill-sql` and the Forwarder of Watermill, `queryclient` on `context` and `sony/gobreaker/v2`, `token` on `golang-jwt/jwt/v5` and `crypto/ed25519`. Each `doc.go` names its library.
- Only the glue is ours: the wiring of each library, the task that deletes the old rows of the outbox and the metrics of the pending ones, the deduplication on the identifier of the envelope. Don't hand-write what a chosen library covers, and don't replace one, without a new decision.
- Watermill's `Message` type stays inside the chassis and the adapters, never in a domain or an application service. No OpenTelemetry.
- A query to another service goes through a `queryclient.Client`, one per callee, passed to the client `oapi-codegen` generates with `WithHTTPClient`. The adapter turns any error of the call into a refused command (503), and maps each 4xx to its meaning in Contracts.

## State

`server`, `health`, `config` (`PORT`, `DATABASE_URL`, `KAFKA_BROKERS`), `logging`, `metrics` (Prometheus HTTP metrics, and `Registerer` for the metrics of the other packages) and `queryclient` are implemented, with a runnable example in `cmd/example`. `token` signs and checks the sign-in token of ADR-09, and `config` reads its keys from `TOKEN_PRIVATE_KEY` and `TOKEN_PUBLIC_KEY`. `postgres` opens the pgx pool and applies the goose migrations under an advisory lock (`Open`); the pool's `Ping` is the readiness check. `event` holds the envelope generated from `api/envelope.schema.json` and the synchronous Kafka publisher keyed by the aggregate. `consumer` applies each event once, in the transaction of its change. `outbox` writes the events in the transaction of the command, sends them with the Forwarder of Watermill, deletes the sent rows written more than a day ago and measures the pending ones. No service wires `consumer` or `outbox` yet.
