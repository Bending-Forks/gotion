# Editing

- From the root of the repository: `npm run build -w services/editing` checks the types with `tsc`, `npm test -w services/editing` runs the tests, `npm start -w services/editing` starts the service. The tests of the PostgreSQL adapter need `TEST_DATABASE_URL`, a server where they may create and drop databases, such as the `editing-db` of `compose.yaml` (`postgres://editing:editing@localhost:5435/editing`), and are skipped without it.
- `@confluentinc/kafka-javascript` is a native binding, with prebuilt binaries up to Node.js 24, the version of the project (`.nvmrc`, `engines`); on a later Node.js npm compiles it, which needs a C and C++ toolchain and can fail. Use Node.js 24.
- Node.js runs the TypeScript sources as they are, stripping the types: only erasable syntax (no `enum`, `namespace` or parameter properties), relative imports end in `.ts`, and type-only imports use `import type`. `tsc` enforces it.
- Tests use `node:test` and `node:assert/strict`, in `*.test.ts` files next to the code they test.
- `src/domain/` imports only `@gotion/crdt`: no `node:` module, no library. `src/app/` imports only `src/domain/`, which re-exports the types of the CRDT that the application services name.
- The chassis is Fastify with its plugins and the libraries ADR-07 chose, not a framework and not written from scratch: `fastify` for REST, `@fastify/websocket`, `@confluentinc/kafka-javascript` for the producer and the consumers, `pg`, `node-pg-migrate`, `fastify-metrics` on `@prometheus-io/client` (the successor of `prom-client`), `opossum` for the circuit breaker, pino (part of Fastify) for the logs; the types from `json-schema-to-typescript` and `openapi-typescript`. They are imported only in `src/adapters/` and `src/main.ts`. `npm run lint` fails on a library or a `node:` module imported by `src/domain/` or `src/app/` outside their tests.
- `npm run gen:events -w services/editing` writes the types of the events of `api/events/` into `src/adapters/events/`; run it after changing a schema there, and never edit those files by hand.
- Page Deleted and Block Deleted are published straight to Kafka, with no outbox (ADR-05). The append to the session log commits before the ack (ADR-06).
- The roles are a local copy kept from the events of Membership through an anticorruption layer; Membership is asked only when the copy has no row (ADR-03). Two adapters do it, as in the hexagonal picture of the report: the Kafka consumer of the events of Membership, in `src/adapters/membership-events/`, whose anticorruption layer turns each event into a call to the application services that update the copy and make a removed member leave the sessions; and the roles adapter, which implements `AccessLookupService` by reading the copy, or else asking Membership. The consumer is the only folder that may import the types of those events: `npm run lint` checks it by the names of the schemas in `services/membership/api/events/`.

## State

The chassis is in `src/adapters/`, wired in `src/main.ts`: configuration from environment variables (`DATABASE_URL`, `KAFKA_BROKERS`, `PORT`, `LOG_LEVEL`), JSON logs by pino, the Kafka client logging through it too, `/health/live`, `/health/ready` (the database, and Kafka by listing the topics through the admin client of the producer) and `/metrics` with `fastify-metrics`, and the `node-pg-migrate` migrations at start under its advisory lock in `wait` mode. The test that two instances apply a migration once takes its PostgreSQL from `TEST_DATABASE_URL`, which the `node` job of the CI sets to the `editing-db` server of `compose.yaml`. `api/` has the OpenAPI specification, with Set title, icon, cover and one query, the workspace of a page, which Discussion asks when it opens a thread since a `PageId` does not tell its workspace, and the AsyncAPI specification, with Page Deleted and Block Deleted. No domain or application service yet.
